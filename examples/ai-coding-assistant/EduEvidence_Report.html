04 Evidence Tribunal

决策：PILOT · 置信度：Moderate

可以主张（CAN CLAIM）

  • AI coding assistants reliably increase task performance during training (completion speed, correctness) — E-001, E-006.
  • Unguarded generative AI access can harm independent problem solving when access is removed — E-004.
  • Guardrail design (hints instead of answers) substantially mitigates the negative learning effect — E-005.
  • Task performance gains do not automatically imply learning gains — E-004 vs E-006 (within-study contrast).

尚不能主张（UNCERTAIN）

  • Whether AI coding assistants improve or preserve actual programming learning in university novices — no direct university-level study in reviewed set.
  • Whether one-week neutral retention (Kazemitabaar 2023) extends to a semester — E-003.

被反驳的主张（CANNOT CLAIM）

  • The claim 'AI tools always improve learning' is contradicted by E-004 (unguarded access, -17% independent exam).

缺失证据

  • RCT of AI coding assistants in university programming courses with retention and no-AI transfer tests.
  • Studies varying AI usage policy within the same course.
  • Longitudinal data on AI dependency beyond one course.

09 Teaching Intervention

目标学习者：university first-year C programming students (60-student lecture-lab class) · 试点时长：8_weeks

AI 使用规则：AI usage is allowed in three explicitly graded modes (explain / collaborate / no-AI-transfer). Copying unexamined AI output is an academic integrity violation and is assessed via the reasoning-trace requirement.

Phase 1 — Independent Foundation

AI 规则：full code generation forbidden; AI allowed only for conceptual explanations

活动：

  • baseline assessment
  • first 2 weeks of assignments completed without any AI code generation

结果检查：baseline task-performance and independent-problem-solving measures

Phase 2 — Explain, Don't Solve

AI 规则：AI may explain but must not produce full solutions

活动：

  • weeks 3-4: AI allowed to explain errors, concepts and debugging approaches

结果检查：mid-pilot quiz without AI

Phase 3 — Structured Collaboration

AI 规则：partial code generation allowed; mandatory written explanation of key logic; submission requires reasoning trace

活动：

  • weeks 5-7: AI allowed to generate partial code; students must explain every AI-generated block in their own words

结果检查：weekly lab completion and code-quality rubric

Phase 4 — Transfer Check

AI 规则：no AI access during transfer assessment

活动：

  • week 8: new programming task completed in a no-AI environment

结果检查：transfer test score, independent problem solving

停止条件

  • transfer-test scores drop significantly below baseline cohort expectations
  • widespread integrity violations in reasoning traces
  • AI dependency signals exceed threshold in risk metrics
  • TA/teacher workload becomes unsustainable

10 Evaluation Plan

研究问题：In a first-year C programming course, does a guardrailed AI coding assistant (explain-only → structured collaboration) improve independent problem solving without increasing AI dependency, compared to no-AI instruction?

基线：week-1 no-AI programming quiz (independent problem solving, completion time)

后测：week-8 no-AI programming quiz (independent problem solving, code quality)

保持测试：final exam (week 16) — delayed measure 8 weeks after pilot

迁移测试：week-8 novel programming task in a strictly no-AI environment

过程指标

  • weekly lab completion rate
  • AI usage logs: prompts submitted, copied blocks, reasoning traces
  • help-seeking behavior counts

学习指标

  • independent problem solving (no-AI quizzes)
  • code quality rubric
  • retention on final exam
  • transfer task score

风险指标

  • AI dependency index (usage without understanding, from reasoning-trace quality)
  • academic integrity violations
  • self-reported over-reliance
  • false confidence (post-quiz confidence vs actual score)

成功阈值：treatment group shows non-inferior independent problem solving (delta within 5%) AND superior or equal retention AND AI dependency index below threshold; if independent problem solving declines >10%, the pilot is judged unsuccessful regardless of task-performance gains.

分析计划：pre-registered comparison of treatment vs comparison sections on baseline-adjusted learning metrics (ANCOVA); task-performance metrics reported separately from learning metrics; subgroup analysis by prior programming competency; stop-condition monitoring at weeks 3, 5, 7.
