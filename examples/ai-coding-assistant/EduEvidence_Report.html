04 证据裁决

本节回答：证据允许我们主张什么、不允许主张什么？缺失的关键证据是什么？

决策：试点验证 · 置信度：中

可以主张

  • AI 编程助手可靠地提升训练期间的任务表现（完成速度、正确率）——E-001、E-006。
  • 无护栏的生成式 AI 访问在访问被移除后可能损害独立问题解决能力——E-004。
  • 护栏设计（提示而非答案）大幅缓解负面学习效应——E-005。
  • 任务表现提升并不自动意味着学习提升——E-004 对 E-006（研究内对照）。

尚不能主张

  • AI 编程助手是否提升或保持大学新手的真实编程学习——评审集中没有直接的大学层面研究。
  • 一周中性保持力（Kazemitabaar 2023）能否延续到一学期——E-003。

被反驳的主张

  • “AI 工具总是提升学习”的主张被 E-004 反驳（无护栏访问，独立考试低 17%）。

缺失证据

  • 大学编程课程中带保持力与无 AI 迁移测试的 AI 编程助手随机对照试验。
  • 同一课程内变化 AI 使用政策的研究。
  • 超过一门课程的 AI 依赖纵向数据。

09 教学干预

本节回答：如果试点，AI 使用规则怎么分阶段放开？什么情况必须叫停？

目标学习者：大学一年级 C 语言编程学生（60 人讲授+实验班） · 试点时长：8_weeks

AI 使用规则：AI 使用分三种明确计分模式（解释 / 协作 / 无 AI 迁移）。未经审视直接复制 AI 输出属于学术诚信违规，通过推理痕迹要求评估。

阶段 1 — 独立基础

AI 规则：完全禁止代码生成；AI 仅可用于概念解释

活动：

  • 基线评估
  • 前两周作业完全不用 AI 生成代码

结果检查：基线任务表现与独立问题解决测量

阶段 2 — 解释而非代答

AI 规则：AI 可解释但不得给出完整解答

活动：

  • 第 3-4 周：允许 AI 解释错误、概念与调试方法

结果检查：试点中期无 AI 测验

阶段 3 — 结构化协作

AI 规则：允许部分代码生成；必须书面解释关键逻辑；提交需附推理痕迹

活动：

  • 第 5-7 周：允许 AI 生成部分代码；学生必须用自己的话解释每个 AI 生成的代码块

结果检查：每周实验完成率与代码质量评分

阶段 4 — 迁移检验

AI 规则：迁移评估期间不得使用 AI

活动：

  • 第 8 周：在无 AI 环境中完成新的编程任务

结果检查：迁移测试成绩、独立问题解决

停止条件

  • 迁移测试成绩显著低于基线班预期
  • 推理痕迹中普遍出现诚信违规
  • 风险指标中 AI 依赖信号超阈值
  • 助教/教师工作量不可持续

10 评价方案

本节回答：如何设计实验验证效果？测什么指标、成功标准是什么？

研究问题：在大一 C 语言编程课中，相比无 AI 教学，带护栏的 AI 编程助手（仅解释→结构化协作）能否在不增加 AI 依赖的情况下提升独立问题解决能力？

基线：第 1 周无 AI 编程测验（独立问题解决、完成时间）

后测：第 8 周无 AI 编程测验（独立问题解决、代码质量）

保持测试：期末考试（第 16 周）——试点结束后 8 周的延迟测量

迁移测试：第 8 周严格无 AI 环境中的新编程任务

过程指标

  • 每周实验完成率
  • AI 使用日志：提交的提示、复制的代码块、推理痕迹
  • 求助行为计数

学习指标

  • 独立问题解决（无 AI 测验）
  • 代码质量评分
  • 期末保持力
  • 迁移任务成绩

风险指标

  • AI 依赖指数（不理解的使用，来自推理痕迹质量）
  • 学术诚信违规
  • 自报过度依赖
  • 虚假自信（测验后自信度 vs 实际得分）

成功阈值：干预组独立问题解决非劣（差异在 5% 内）且保持力优于或等于对照且 AI 依赖指数低于阈值；若独立问题解决下降超过 10%，无论任务表现收益如何，试点判定失败。

分析计划：预注册的基线校正学习指标对比（ANCOVA）；任务表现指标与学习指标分开报告；按先前编程能力做亚组分析；第 3、5、7 周监控停止条件。

09 Teaching Intervention

If we pilot, how should AI usage rules phase in, and when must we stop?

Target learners：university first-year C programming students (60-student lecture-lab class) · Pilot duration：8_weeks

AI usage policy：AI usage is allowed in three explicitly graded modes (explain / collaborate / no-AI-transfer). Copying unexamined AI output is an academic integrity violation and is assessed via the reasoning-trace requirement.

Phase 1 — Independent Foundation

AI rule：full code generation forbidden; AI allowed only for conceptual explanations

Activities：

  • baseline assessment
  • first 2 weeks of assignments completed without any AI code generation

Outcome check：baseline task-performance and independent-problem-solving measures

Phase 2 — Explain, Don't Solve

AI rule：AI may explain but must not produce full solutions

Activities：

  • weeks 3-4: AI allowed to explain errors, concepts and debugging approaches

Outcome check：mid-pilot quiz without AI

Phase 3 — Structured Collaboration

AI rule：partial code generation allowed; mandatory written explanation of key logic; submission requires reasoning trace

Activities：

  • weeks 5-7: AI allowed to generate partial code; students must explain every AI-generated block in their own words

Outcome check：weekly lab completion and code-quality rubric

Phase 4 — Transfer Check

AI rule：no AI access during transfer assessment

Activities：

  • week 8: new programming task completed in a no-AI environment

Outcome check：transfer test score, independent problem solving

Stop conditions

  • transfer-test scores drop significantly below baseline cohort expectations
  • widespread integrity violations in reasoning traces
  • AI dependency signals exceed threshold in risk metrics
  • TA/teacher workload becomes unsustainable

10 Evaluation Plan

How do we evaluate real effects: metrics, comparison, success threshold?

Research question：In a first-year C programming course, does a guardrailed AI coding assistant (explain-only → structured collaboration) improve independent problem solving without increasing AI dependency, compared to no-AI instruction?

Baseline：week-1 no-AI programming quiz (independent problem solving, completion time)

Post test：week-8 no-AI programming quiz (independent problem solving, code quality)

Retention：final exam (week 16) — delayed measure 8 weeks after pilot

Transfer：week-8 novel programming task in a strictly no-AI environment

Process metrics

  • weekly lab completion rate
  • AI usage logs: prompts submitted, copied blocks, reasoning traces
  • help-seeking behavior counts

Learning metrics

  • independent problem solving (no-AI quizzes)
  • code quality rubric
  • retention on final exam
  • transfer task score

Risk metrics

  • AI dependency index (usage without understanding, from reasoning-trace quality)
  • academic integrity violations
  • self-reported over-reliance
  • false confidence (post-quiz confidence vs actual score)

Success threshold：treatment group shows non-inferior independent problem solving (delta within 5%) AND superior or equal retention AND AI dependency index below threshold; if independent problem solving declines >10%, the pilot is judged unsuccessful regardless of task-performance gains.

Analysis plan：pre-registered comparison of treatment vs comparison sections on baseline-adjusted learning metrics (ANCOVA); task-performance metrics reported separately from learning metrics; subgroup analysis by prior programming competency; stop-condition monitoring at weeks 3, 5, 7.
